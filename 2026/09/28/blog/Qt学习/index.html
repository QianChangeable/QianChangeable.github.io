现在我们有一个窗口了！加一个按钮试试

添加了两个头文件 QPushButton QVBoxLayout，一个是按钮 button 控件，一个是布局管理器 layout。

在 QWidget window 之后，添加按钮，并用布局管理其几何。这三行是什么意思呢？

声明一个 QPushButton* 类型的指针 button，指向一个对象 QPushButton，这个对象是在堆上创建（new 了一个对象）的。传参为 "Click me!"，在按钮上显示文字。此时尚未加入父控件，也未纳入布局。

然后第二行：声明一个垂直布局 layout。传参 &window，将布局安装到 window（QWidget 的 layout），即 window 拥有该 QVBoxLayout，由其负责子控件的几何布局。

layout->addWidget(button);

  • 将 button 加入该布局管理的控件列表；
  • 建立控件树中的父子关系（button 成为 window 的子控件）；
  • 之后由布局计算并设置 button 的位置与尺寸。

现在只有垂直布局，那有没有其他的布局？水平布局？

有的兄弟，有的。

类 方向/作用
QVBoxLayout 垂直：子控件自上而下排列
QHBoxLayout 水平：子控件自左而右排列
QGridLayout 网格：按行、列放在单元格里
QFormLayout 表单：常用于「左侧标签 + 右侧输入框」两列
QStackedLayout 叠放：同一区域只显示其中一个子控件（类似翻页）

参数 值 作用

为什么要 connect 两次？因为跨了两段：树 → 侧边栏，侧边栏 → 编辑区。

第一段：QTreeView::clicked 传来的是 QModelIndex，不是路径字符串；还要判断是不是文件夹。所以必须进 onTreeClicked，过滤后 emit fileSelected(path)。槽里再 emit 不是多余转手，是改参数类型并丢掉文件夹点击。

第二段：MainWindow 把 fileSelected 连到 ContentArea::openFile，编辑区只认 QString 路径。

若两个信号参数类型完全一样，可以把信号直接连到信号，不必写中间槽。这里 clicked(QModelIndex) 和 fileSelected(QString) / openFile(QString) 对不上，又要判断是否文件夹，所以不能省掉这一层。

真正要自己想清楚的是：端口在不在听，以及如何把 .md 路径拼成预览 URL。

点文件时先确认本机预览服务还活着。用 QTcpSocket 短超时连 127.0.0.1:4000（hexo server 默认端口）：

连不上就提示先跑 hexo server，不要去 load 一个必然失败的地址。

步骤：

  1. 从绝对路径里截出 /source/_posts/ 后面的相对路径，去掉 .md
  2. 读文件头 date:，取出年 / 月 / 日
  3. 拼成 /yyyy/MM/dd/相对路径/，再交给 QUrl（中文路径由 Qt 做百分号编码）

openFile 里变成：测端口 → 拼 URL → m_preview->load(url)。侧边栏的 fileSelected 和 MainWindow 的 connect 不用改。
