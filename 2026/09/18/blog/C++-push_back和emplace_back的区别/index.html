C++ push_back和emplace_back的区别

push_back()和emplace_back()的区别，细细道来

为什么 push_back 要先有一个已经造好的元素

push_back 插入的是已经构造好的元素，不是构造这个元素用的原材料。

对 vector<T>，T 就是元素类型。vector<string> 的 T 是 string。标准库给 push_back 写了两个重载：const T& 拷贝已有元素，T&& 移动已有元素。调用处手里必须已经有这个对象。

libc++ 的 __vector/vector.h 把这个已有对象转发给 emplace_back。拷贝重载调用 emplace_back(__x)。移动重载调用 emplace_back(std::move(__x))。

为什么 emplace_back 收的是构造函数的参数

emplace_back 不要求你先造好元素。它的形参是 _Args&&...，也就是构造 T 时会用到的那些实参，再转发到元素所在的内存。

有剩余容量时，emplace_back 调用 __emplace_back_assume_capacity(std::forward<_Args>(__args)...)。

__emplace_back_assume_capacity 再调用 __alloc_traits::construct。vector 里 __alloc_traits 是 allocator_traits<allocator_type>。construct 的实参就是这些构造参数。

push_back 在源码里调用 emplace_back

libc++ 的 push_back 在源码里直接调用 emplace_back。

拷贝 push_back 传入的是已经存在的 __x。移动 push_back 传入的是 std::move(__x)。

emplace_back 随后仍走到 allocator_traits::construct。此时推出来的 _Args 是 T 或 T&&，construct 调用的是 T 的拷贝构造或移动构造。

比较。这次转发只是让 push_back 复用 emplace_back 的插入代码。代价仍是对已有 T 做一次拷贝或移动。

438 里的 push_back(i)

对已经算好的 int，emplace_back 并不比 push_back 少一次构造。

438 题解里 ans 的类型是 vector<int>，i 已经是 int。ans.push_back(i) 会变成 emplace_back(i)，construct 仍然是把这个 int 拷贝或移动进缓冲区。

explicit 时不要一律改成 emplace_back

emplace_back 可以调用 explicit 构造函数，所以不能把所有 push_back 改成 emplace_back。

push_back 的形参已经是 T。push_back(1) 必须先能把 1 隐式转换成 T。

emplace_back(1) 把 1 交给 construct。它会调用 T(int)，即使这个构造函数是 explicit。

比较。这里改掉的是能否编译，不是少一次对已有 T 的拷贝或移动。
