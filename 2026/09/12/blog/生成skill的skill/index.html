生成skill的skill，你搁这搁这呢？

1. 问题定义

本次目标不是「让 Agent 多会一项业务能力」，而是先装一套 约束如何编写 skill 的 skill，再用它产出本仓库的第一份业务 skill。

输入是两个公开仓库：

  • obra/superpowers
  • anthropics/skills

二者都遵守 Agent Skills 格式（目录 + SKILL.md），职责不同：

仓库 层级 实际作用
anthropics/skills 规范 + 示例 + 评测工厂 skill-creator 负责脚手架、校验、eval；其余多为成品能力（pdf / pptx / mcp-builder 等）
obra/superpowers 编码方法论 brainstorm → plan → TDD → 子 agent 执行 → review；其中 writing-skills 约束「如何写 skill」
Cursor 内置 create-skill 编辑器适配 规定 Cursor 落盘路径与 frontmatter

需求在交互中被收敛为三句话：

  1. 不要整仓 Superpowers，不要评测工具链。
  2. 不要把 meta-skill 理解成「用它去生成周报 Markdown」。meta-skill 产出的是说明书；干活的是说明书约束下的业务 skill。
  3. 要的是 写作约束（何时写、何时不写、description 禁止概括流程、防 Agent 走捷径），不是 init_skill.py / eval-viewer。

选型结论：部署 Superpowers 的 writing-skills 单份，不装插件全家桶。Cursor 路径规则仍沿用 create-skill。

2. 部署 writing-skills（全局）

2.1 范围

  • 目标路径：~/.cursor/skills/writing-skills/（个人全局，跨项目）
  • 禁止写入：~/.cursor/skills-cursor/（编辑器内置）
  • 不安装：Superpowers 其余 skill、Claude Code marketplace、Python eval 栈

2.2 交互步骤

  1. 对齐候选。 对比 create-skill、skill-creator、writing-skills 三份 SKILL.md。skill-creator 重心在评测闭环；writing-skills 重心在 description SDO、When NOT、RED-GREEN-REFACTOR。
  2. 校正过满结论。 另一路建议把 writing-skills 说成「唯一、零依赖」。核对原文后否决：它声明依赖 superpowers:test-driven-development，并要求子 agent 压力测试。约束方向正确，安装范围仍应裁剪。
  3. 确认安装。 用户明确「不够狠，配置到 Cursor 全局 skill」。

2.3 落盘与故障回退

按依赖从宽到窄尝试三次：

  1. git sparse-checkout 只拉 skills/writing-skills。失败：GitHub HTTP2 framing / checkout 中断（exit 128）。
  2. curl 直拉 raw 文件。失败：全局目录写入被策略拦截。
  3. WebFetch 取原文 → 用户批准后写入 ~/.cursor/skills/。成功。

配套文件一并落下：anthropic-best-practices.md、testing-skills-with-subagents.md、persuasion-principles.md、examples/。render-graphs.js 未拷（仅渲染流程图，与写作约束无关）。

2.4 Cursor 适配补丁

原 skill 写的是 ~/.claude/skills/，并 MUST 加载 Superpowers TDD。本机没有那套运行时，因此在 SKILL.md 顶部增加覆盖规则：

  • 个人目录 ~/.cursor/skills/，项目目录 <repo>/.cursor/skills/
  • 找不到 test-driven-development 时不拒绝、不空转；RED-GREEN-REFACTOR 按本文档与 testing-skills-with-subagents.md 执行，子 agent 用 Cursor Task
  • 与 create-skill 同时命中时：写作约束跟 writing-skills，路径跟 Cursor
  • 部署完成条件：文件出现在上述目录，不要求向 Superpowers 提 PR

新会话才能稳定发现刚装的全局 skill，因此安装结束后要求换一轮对话再生成业务 skill。

3. 用 writing-skills 生成第一个业务 skill

第一份业务 skill 是本博客的 creating-hexo-posts，路径：.cursor/skills/creating-hexo-posts/SKILL.md（项目级，只约束这个仓库）。

3.1 Discovery

按 writing-skills：先问用途、存放位置、触发词、成功标准，再写文件。确认结果：

  • 用途：新建 source/_posts 骨架，以及预览后发布到 GitHub Pages
  • 位置：项目 skill，不进全局
  • 触发：写博客 / hexo new / 发布 / hexo d / 预览
  • 正文由用户写；Agent 不代写文章

3.2 RED：无 skill 时的基线

用子 agent 加压（赶时间、标题已给、要求直接生成 / 直接 hexo d）。无约束时的典型偏离：

  • 跳过清单，自拟或直接落盘
  • <!--more--> 后写满正文
  • 创建当轮顺便预览或部署
  • 「别预览了」则跳过 hexo s 直接 hexo d
  • 部署与源码 commit/push 绑死或漏做

这些借口写进 skill 的 Rationalizations / Red flags，而不是凭空列规则。

3.3 GREEN：最小可执行文档

creating-hexo-posts 拆成两条互斥路径，禁止同一轮混用：

Create path

  1. 第一轮只发完整清单（title / date / categories / tags / sticky / 摘要），即使部分字段已给出。
  2. 无 title 不生成文件；date 可默认当前时间。
  3. <!--more--> 后必须为空。
  4. 不跑 hexo new。摘要缺省写入固定占位句 可花谢花开，终有梦醒时分.。

Publish path

  1. 先起 npx hexo server，给出 http://localhost:4000。
  2. 预览确认后，同一轮执行 hexo clean && generate && d，并只 git add source/_posts 后 commit / push。
  3. 「别预览了 / 已经预览过了」不构成跳过第 1 步的理由。

description 只写触发条件，不把上述流程写进 YAML，避免 Agent 只读摘要、跳过正文。

3.4 REFACTOR

用户改了两处发布约定，skill 跟着改，并再跑子 agent：

  1. 发布必须先预览再问是否 hexo d。
  2. 预览确认后，静态站部署与 hexo-source 备份合并为一步，不再二次询问 git。

每轮对照：催促跳过预览时是否仍先 hexo s；确认发布后是否还多问一次 push。不通过就补 Red flags，再测。

4. 闭环验证

本篇文章的 md 骨架即由 creating-hexo-posts 生成：清单 → 用户填 title / categories / tags / 摘要 → 写入 source/_posts/生成skill的skill.md，<!--more--> 后为空。正文是后续对已有文件的修改，skill 明确把「改已有文章正文」划出 Create path。发布未执行。

5. 产物清单

使用约定：

  • 再写 skill → 走全局 writing-skills（需要时做 RED/GREEN）
  • 再写博客骨架或发布 → 走项目 creating-hexo-posts
  • 批量脚手架与量化评测 → 才考虑 Anthropic skill-creator；当前未部署
